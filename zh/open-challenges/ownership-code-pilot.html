開源試點 · 邀請貢獻者

AI 能準備有用的回答，也知道何時該交給真人嗎？

一起建立公開的 AI 實作流程：理解客戶問題、找到可追溯來源、準備回應草稿、顯示不確定性，並由真人決定核准、修改、拒絕或接手。

Open Source合成資料可用人工審閱自備模型與 Token

貢獻透過 Issue、commit 與 Pull Request 公開留名；參與不保證採用、報酬、聘僱或股權。

可審閱的流程

  1. 1理解問題使用核准或合成輸入
  2. 2找到支持證據保留來源與不確定性
  3. 3準備回應草稿有用、可追溯、不冒充真人
  4. 4由真人決定核准、修改、拒絕或接手
  5. 5評量是否有效記錄證據、成本與限制

我們要解的題目

用有用的證據建立信任，不使用隱性操控。

小型團隊能否減少理解客戶問題與準備回應所需的時間，同時讓事實、來源、不確定性、同意與人的責任保持可見？

為什麼值得關注

真實問題、可重用方法，以及公開可檢視的證據。

01 · 真實情境

從正在發生的工作開始

第一個情境來自企業經營者的關係建立流程，判斷與信任都是必要條件。

02 · 開放價值

不是企業獨占的免費交付

出題企業可以取用成果，貢獻者與其他組織也能依授權重用開源核心。

03 · 容易開始

不必等待私有資料

十二筆合成情境與獨立小任務，讓任何人從第一天就能安全開始。

04 · 多種專長

不只是程式比賽

研究、UX、評量、文件、安全與工程都有清楚可交付的工作。

05 · 負責任 AI

人工審閱是必要邊界

參考實作不冒充真人、不爬私人社群，也不自動發送對外訊息。

06 · 可攜與可負擔

自備模型與 Token

核心不綁模型供應商；每個部署者自行提供帳號並負擔自己的使用費用。

怎樣才算成功

不是宣稱「Agent 可以用」，而是留下別人能檢查的證據。

第一個里程碑是可審閱的 baseline：呈現哪裡有幫助、哪裡失敗、需要多少成本，以及何時必須交給真人。

問題判斷相關

人工審閱者同意問題與痛點分類符合情境。

內容有來源

重要事實可回到核准資料；沒有支持的陳述會被拒絕。

不確定性可見

資訊不足與限制會被顯示，而不是默默猜測。

安全交給真人

高風險、不清楚或重視關係的情況會轉交真人。

可以重現

fixture、模型版本、審閱步驟與預期結果都有紀錄。

成本透明

回報 Token 或估計費用，核心也能用 mock 路徑執行。

開啟 Issue #12 ↗

清楚的資料邊界

Open Source 不等於公開每個人的資料。

可以公開

  • 程式、prompt、schema 與評量方法
  • 合成或核准的去識別化範例
  • 公開來源連結與簡短歸因摘要
  • Issue、設計決策及可重現測試

絕對不放進 Repository

  • 客戶或潛在客戶名單與聯絡資料
  • 私人社團貼文、訊息或會議逐字稿
  • 帳密、Token 或私人帳號設定
  • 冒充真人、隱性操控、垃圾訊息或未核准聯繫
